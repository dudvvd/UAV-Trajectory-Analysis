# UAV 相邻图像轨迹估计

本项目从无人机红外相机相邻图片出发，使用传统计算机视觉方法估计相对运动，并从首帧已知经度、纬度、高度递推后续轨迹。程序会把估计结果与 CSV 中的真实定位数据对比，输出误差 CSV 和轨迹变化图。

当前实现不使用深度学习训练网络，主要用于验证“相邻图像关系能否反映无人机轨迹变化”，并为后续接入相机、姿态和传感器数据预留接口。

## 重要说明

当前数据只有单目相邻图像和每帧真实经纬高，没有相机内参、姿态角、云台角、地面平面约束等信息。因此，单目图像本身不能唯一恢复真实尺度、绝对航向和完整三维位移。本项目采用工程上常见的可配置假设：

- 使用相机水平视场角 `--horizontal-fov-deg` 和当前高度把像素位移换算为米。
- 使用 `--yaw-deg` 假设图像坐标系与 ENU 坐标系的夹角。
- 默认保持首帧高度；可用 `--estimate-altitude` 尝试从 `orb_affine` 仿射尺度估计高度变化。
- 真实定位数据只用于首帧初始化和后续误差验证，不在默认递推过程中更新估计位置。
- `--calibration-frames` 会使用首帧之后的真实定位数据拟合像素到米的映射，只适合做标定和算法上限评估，不代表纯部署输入。

## 方法局限性

### 1. 单目图像存在尺度不确定性

仅凭相邻两张单目图片，可以较稳定地估计图像上的像素平移、旋转或缩放趋势，但无法仅从图像唯一确定“1 个像素对应多少米”。当前代码通过高度和视场角假设进行换算，因此：

- `--horizontal-fov-deg` 不准确会直接造成水平距离误差。
- 高度越高，同样像素位移代表的实际距离越大。
- 如果相机不是严格俯视地面，简单的像素到地面距离换算会产生系统误差。

### 2. 缺少无人机姿态和相机朝向

图像坐标系与地理 ENU 坐标系之间的夹角目前由 `--yaw-deg` 人工给定。若实际航向、云台角或相机安装角未知，图像中“向右/向上”的运动不一定对应真实世界的东/北方向。因此默认结果可能出现方向旋转、镜像或水平误差积累。

### 3. 高度估计不稳定

`orb_affine` 可以从图像仿射矩阵中得到尺度变化，但该尺度同时受以下因素影响：

- 地面起伏和场景深度变化。
- 相机俯仰/横滚变化。
- 图像纹理质量、红外成像噪声和匹配外点。
- 真实无人机高度变化和相机姿态变化耦合在一起。

因此当前默认固定首帧高度。`--estimate-altitude` 仅作为实验选项，不建议在缺少相机姿态和地面模型时直接作为可靠高度结果。

### 4. 误差会随时间递推累积

当前轨迹从首帧开始逐帧积分相邻位移，中途不使用真实定位纠偏。任何单帧估计误差都会传递到后续帧，长序列会出现漂移。全量 2.1 万帧运行时，轨迹漂移通常会明显大于短片段测试。

### 5. 红外图像特征质量会影响匹配

红外图像可能存在纹理少、局部重复、曝光变化、运动模糊、画面停滞或压缩伪影等问题。ORB 特征和相位相关法都依赖图像内容稳定，低纹理或重复纹理区域会导致匹配置信度下降。

### 6. 当前模型假设地面近似平面

像素位移到地面位移的换算默认场景接近水平地面。如果画面包含明显高差、建筑物、树木或非平面目标，不同区域的像素运动对应的真实距离不同，简单仿射/平移模型会产生偏差。

### 7. CSV 真值仅用于验证

默认递推时只使用初始帧真实经纬高，后续帧的真实经纬高仅用于计算误差。如果希望在真实系统中提高轨迹稳定性，应考虑融合 GPS/RTK/IMU，而不是完全依赖相邻图像积分。

## 建议补充的数据

若希望显著提升精度，建议后续尽量补充以下数据。数据越完整，越能从“近似视觉位移估计”升级到更严谨的视觉惯性/几何定位。

| 数据类型 | 具体内容 | 作用 |
| --- | --- | --- |
| 相机内参 | 焦距 `fx/fy`、主点 `cx/cy`、分辨率 | 将像素坐标转换为相机归一化坐标，替代粗略 FOV 假设 |
| 畸变参数 | 径向/切向畸变参数 | 先去畸变再匹配，减少边缘区域几何误差 |
| 相机外参 | 相机相对无人机机体的安装位置和旋转 | 将相机坐标系运动转换到无人机机体系 |
| 无人机姿态 | 每帧 roll、pitch、yaw 或四元数 | 将图像运动准确旋转到 ENU/NED 世界坐标系 |
| 云台姿态 | 每帧云台 yaw、pitch、roll | 处理相机不是固定安装或云台主动稳定的情况 |
| 准确时间同步 | 图片时间戳与定位/IMU 时间戳同步关系 | 避免图像和传感器记录错帧 |
| 速度信息 | GPS/RTK/IMU 推算速度，或飞控速度日志 | 为视觉估计提供尺度约束和异常检测 |
| 高精度定位 | RTK/GNSS 真值或基站后处理轨迹 | 用于标定、评估和轨迹纠偏 |
| 地面高程/DEM | 拍摄区域地面高程或近似平面高度 | 将图像射线投影到真实地面，提高尺度精度 |
| 相机曝光/成像参数 | 曝光、增益、焦距是否变化 | 分析图像匹配失败原因，优化预处理 |

最小推荐补充组合：

1. 相机水平/垂直 FOV 或完整内参。
2. 每帧无人机 yaw、pitch、roll。
3. 相机安装角或云台角。
4. 图片和飞控日志的准确时间同步关系。

有了以上数据后，轨迹估计可以从当前的经验参数模型，改进为基于相机投影几何的地面位移估计。

## 后续改进方向

### 1. 使用相机内参和姿态进行几何投影

当前通过 `horizontal_fov_deg + altitude` 近似像素到米的比例。更好的做法是：

1. 用相机内参把匹配点转成归一化相机射线。
2. 用无人机姿态、云台姿态和相机外参把射线转到世界坐标系。
3. 将射线与地面平面或 DEM 相交。
4. 由相邻帧地面点变化估计真实 ENU 位移。

这可以显著减少航向和尺度假设带来的系统误差。

### 2. 引入 IMU/GNSS 融合

可以使用扩展卡尔曼滤波、因子图优化或滑动窗口优化，将视觉相对位移、IMU 短时运动和 GNSS/RTK 绝对位置融合：

- 视觉提供相邻帧相对约束。
- IMU 提供高频姿态和短时运动连续性。
- GNSS/RTK 提供低频绝对位置纠偏。

这样可以抑制长序列漂移，并在图像匹配失败时保持轨迹连续。

### 3. 增强图像预处理和特征匹配

红外图像可以尝试以下传统视觉增强：

- CLAHE 局部直方图均衡。
- 图像去噪和锐化。
- 网格化特征点筛选，避免特征集中在局部区域。
- KLT/Lucas-Kanade 光流跟踪短时连续特征。
- ORB、SIFT、AKAZE 等多方法对比。
- 使用 RANSAC 后进一步检查内点空间分布。

### 4. 增加异常帧处理

建议对每一帧输出的 `confidence`、`matches`、`inliers`、`scale` 和单帧位移做质量检查：

- 匹配数或内点数过低时跳过该帧。
- 单帧位移突变时使用速度约束限幅。
- 连续低置信度时触发重定位或改用传感器预测。
- 对估计轨迹做滑动窗口平滑，而不是简单逐帧累加。

### 5. 支持分段标定和参数搜索

当前 `--calibration-frames` 只做简单线性映射标定。后续可以扩展为：

- 使用前一小段数据自动估计 `yaw_deg` 和像素到米比例。
- 按飞行阶段分段标定，适应高度和姿态变化。
- 自动搜索 `horizontal_fov_deg/yaw_deg`，以短验证段误差最小为目标。
- 输出推荐参数，供后续纯图像递推使用。

### 6. 引入地图或正射影像匹配

如果有拍摄区域的底图、正射影像或地理参考地图，可以把每帧图像与地图匹配，获得绝对位置约束。这会比单纯相邻帧积分更稳定，尤其适合长航线。

### 7. 代码工程化改进

后续可以继续完善：

- 增加单元测试和小样本回归测试。
- 增加配置文件，统一管理相机参数和运行参数。
- 支持批量实验和自动生成评估报告。
- 保存匹配可视化图，便于人工诊断失败帧。
- 增加日志系统，记录每次实验的参数、版本和结果。

## 环境安装

按需求使用预先准备好的 conda 环境 `uav`：

```powershell
conda activate uav
python -m pip install -r requirements.txt
python -m pip install -e .
```

若不安装为包，也可以在项目根目录临时设置：

```powershell
$env:PYTHONPATH = "src"
```

## 数据结构

项目默认读取：

- 图片目录：`data/IR-image`
- 定位文件：`data/定位数据.csv`

CSV 需要包含字段：

```text
时间戳,经度,纬度,高度
```

图片文件名需要是时间戳，例如 `1734763664200.jpg`。程序会按时间戳把图片和定位记录做内连接。

## 快速测试几张图片

从第 0 帧开始，只处理 10 帧：

```powershell
conda run -n uav python run_trajectory.py --max-frames 10 --print-rows 10
```

从中间某段开始测试：

```powershell
conda run -n uav python run_trajectory.py --start-index 500 --max-frames 20 --print-rows 20
```

使用前 10 帧真值进行短段标定评估：

```powershell
conda run -n uav python run_trajectory.py --max-frames 10 --print-rows 10 --calibration-frames 10
```

输出包含：

- `outputs/orb_affine_start*_n*_results.csv`：逐帧真实值、预测值、误差和图像匹配信息。
- `outputs/orb_affine_start*_n*_trajectory.png`：真实轨迹与估计轨迹对比图。

## 运行全部数据

```powershell
conda run -n uav python run_trajectory.py
```

全量数据约 2.1 万张图片，运行时间取决于 CPU 性能。可以通过 `--max-width` 降低处理分辨率来提速，例如：

```powershell
conda run -n uav python run_trajectory.py --max-width 640
```

## 方法对比

项目实现了两种非深度学习方案：

- `orb_affine`：ORB 特征点 + KNN 匹配 + RANSAC 部分仿射矩阵，可估计平移和尺度，默认方法。
- `phase`：相位相关法，只估计全局平移，速度快，适合作为对照。

单独指定方法：

```powershell
conda run -n uav python run_trajectory.py --method phase --max-frames 50
```

同一段数据对比两种方法：

```powershell
conda run -n uav python compare_methods.py --start-index 0 --max-frames 50
```

对比摘要会保存到 `outputs/compare/method_summary.csv`。

## 关键参数

- `--start-index`：选定初始图像在匹配序列中的索引。
- `--max-frames`：处理帧数；不填则处理全部。
- `--horizontal-fov-deg`：相机水平视场角，默认 `60` 度。
- `--yaw-deg`：图像坐标系相对 ENU 的旋转角，默认 `0` 度。
- `--max-width`：图像处理最大宽度，默认 `960`。
- `--estimate-altitude`：使用图像仿射尺度估计高度变化；默认固定首帧高度，这在缺少相机内参/姿态时通常更稳定。
- `--calibration-frames`：使用前 N 帧真值拟合像素位移到 ENU 位移的线性映射。该参数会使用首帧之后的真值，只适合标定和评估，不代表纯部署输入。

## 结果字段

结果 CSV 中主要字段：

- `truth_longitude/truth_latitude/truth_altitude`：CSV 真实位置。
- `pred_longitude/pred_latitude/pred_altitude`：图像递推位置。
- `horizontal_error_m`：水平误差。
- `altitude_error_m`：高度误差。
- `total_error_m`：三维误差。
- `dx_px/dy_px/scale/confidence/matches/inliers`：相邻图像运动估计诊断信息。

## 开发流程总结

1. 读取 CSV 并规范字段，把时间戳转为整数。
2. 扫描图片目录，按图片文件名解析时间戳。
3. 将图片和真实定位按时间戳匹配。
4. 用首帧真实经纬高建立局部 ENU 坐标参考。
5. 对相邻图片计算图像位移和尺度。
6. 根据高度、视场角和航向假设把像素运动转换为 ENU 位移。
7. 从首帧开始递推预测轨迹。
8. 将预测轨迹转回经纬高，与真实数据计算误差。
9. 保存逐帧结果 CSV，并绘制真实轨迹/预测轨迹图。
