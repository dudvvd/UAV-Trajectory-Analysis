# 无人机纯视觉定位方案代码阅读说明

本文档用于快速理解当前项目中已经实现的所有方案，包括主流程视觉里程计、方案 B（强匹配 + 几何）、方案 D（局部地图/关键帧匹配），以及 LoFTR 深度匹配接入方式。

## 1. 项目入口与运行方式

### 1.1 主流程入口 `main.py`

主流程命令：

```powershell
conda run -n uav python main.py --recalibrate --log-level INFO
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--image-dir` | 红外图像目录，默认 `data/IR-image` |
| `--csv` | GPS 真值 CSV，默认 `data/定位数据.csv` |
| `--output-dir` | 输出目录，默认 `output` |
| `--first-image-path` | 指定起始图像，按文件名时间戳匹配 |
| `--initial-longitude` | 第一帧初始经度，不给则使用第一帧 CSV 值 |
| `--initial-latitude` | 第一帧初始纬度 |
| `--initial-altitude` | 第一帧初始高度 |
| `--recalibrate` | 忽略缓存，重新估计相机内参 |
| `--max-frames` | 调试用，只处理前 N 帧 |
| `--log-level` | 日志等级 |

### 1.2 方案 B / D 实验入口 `run_matching_experiments.py`

方案 B/D 对比命令：

```powershell
conda run -n uav python run_matching_experiments.py --max-frames 1000 --matcher orb --output-dir output_matching_orb_1000
```

LoFTR 深度匹配命令：

```powershell
conda run -n uav python run_matching_experiments.py --max-frames 1000 --matcher loftr --output-dir output_matching_loftr_1000
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--matcher` | 匹配后端，可选 `orb`、`sift`、`loftr` |
| `--keyframe-interval` | 方案 D 的关键帧更新间隔，默认 30 |
| `--loftr-width` / `--loftr-height` | LoFTR 输入分辨率，默认 512x384 |
| `--fx` | 手动指定焦距，不给则读取 `output/calibration.json` |

## 3. 主流程方案说明

主流程是一套传统视觉里程计 + 物理约束 + EKF 融合方案。

整体流程：

```text
DataLoader
  -> StartFrameChecker
  -> CameraCalibrator
  -> YawCalibrator
  -> FeatureTracker
  -> FlightPhaseDetector
  -> ScaleEstimator
  -> PhysicsConstraint
  -> pixel_to_geo_delta
  -> EKFLocalizer
  -> Evaluator
```

### 3.1 `DataLoader`

文件：`modules/data_loader.py`

核心类：`DataLoader`

主要函数：

| 函数 | 功能 |
| --- | --- |
| `load()` | 读取图像和 CSV，按时间戳精确匹配 |
| `slice_from()` | 从完整数据中截取起始帧到结束帧 |
| `_read_csv()` | 尝试多种编码读取 CSV |
| `_collect_images()` | 收集图像文件，并用文件名 stem 作为时间戳 |
| `_delta_t_seconds()` | 根据时间戳计算帧间隔，单位秒 |

输出结构：`LoadedData`

字段包括：

- `timestamps`
- `image_paths`
- `gt_lon`
- `gt_lat`
- `gt_alt`
- `delta_t`

注意：GPS 真值在主流程中只用于初始化和最终评估；预测主循环不直接使用后续真值。

### 3.2 `StartFrameChecker`

文件：`modules/start_frame_checker.py`

功能：自动寻找质量合格的起始帧，避免第一帧模糊或特征不足。

主要指标：

- Laplacian 方差，判断模糊度
- Shi-Tomasi 角点数
- 与下一帧做 LK 预跟踪，计算双向跟踪成功率

主要函数：

| 函数 | 功能 |
| --- | --- |
| `check()` | 从指定起点开始最多检查 `START_MAX_CHECK_FRAMES` 帧 |
| `_score_pair()` | 对相邻两帧计算模糊、角点、跟踪比例 |
| `_rank()` | 若没有完全合格帧，选择综合分最高帧 |

### 3.3 `CameraCalibrator`

文件：`modules/camera_calibrator.py`

功能：估计相机内参，并写入 `calibration.json`。

策略：

1. 基础矩阵采样估计焦距
2. 单应矩阵统计估计焦距
3. 经验焦距兜底
4. 可由 `MANUAL_FOCAL_PX` 手动覆盖
5. 主流程中还会调用运动物理先验修正焦距

主要函数：

| 函数 | 功能 |
| --- | --- |
| `estimate()` | 内参估计总入口，支持缓存复用 |
| `_estimate_from_fundamental()` | 多帧基础矩阵估计焦距 |
| `_estimate_from_homography()` | 单应矩阵统计估计焦距 |
| `_focal_from_f_rank()` | 遍历候选焦距，选择最接近本质矩阵奇异值约束的值 |
| `_near_boundary()` | 判断焦距是否贴近合法范围边界，贴边则拒绝 |
| `_save()` | 保存 `calibration.json` |

### 3.4 主流程中的焦距运动先验修正

文件：`main.py`

函数：`_refine_calibration_with_motion_prior()`

作用：

当 F/H 内参估计退化时，仅靠几何估计可能得到过小焦距，导致米/像素过大，进而触发大量物理裁剪。该函数用前若干帧视觉位移和第一帧高度估算一个“至少不违反水平位移物理上限”的焦距下界。

核心公式：

```text
required_fx = pixel_displacement_percentile * initial_alt / MAX_HORIZ_DISP_M * MOTION_PRIOR_MARGIN
```

这个方法不使用 GPS 距离，只使用第一帧高度和物理上限。

### 3.5 `YawCalibrator`

文件：`modules/yaw_calibrator.py`

功能：用前若干帧 GPS 方向和视觉方向估计初始像素坐标到地理坐标的旋转角。

主要函数：

## 4. 方案 B：强匹配 + 几何

文件：`run_matching_experiments.py`

方案 B 的核心思想：

```text
相邻帧图像
  -> 特征/深度匹配
  -> RANSAC 仿射
  -> 像素位移
  -> 固定 yaw 映射到 East/North
  -> 累积轨迹
```

主要函数：`run_scheme_b()`

实现步骤：

1. 读取第一帧高度，计算 `mpp = altitude / fx`
2. 调用 `estimate_yaw_deg()` 用前 50 帧方向标定 yaw
3. 从第 2 帧开始逐帧匹配上一帧
4. `matcher.motion(prev, curr)` 输出像素位移
5. `rotate_pixel_to_en()` 将像素位移转成 East/North
6. 按帧累积位置
7. `finalize_records()` 输出 CSV、轨迹图、误差图和指标

适用场景：

- 相邻帧重叠足够
- 图像纹理稳定
- 相机朝向变化不剧烈

局限：

- 仍是相邻帧积分，漂移会累积
- yaw 若不准确，轨迹方向仍会整体偏
- 不利用局部地图约束

## 5. 方案 D：局部地图 / 关键帧匹配

文件：`run_matching_experiments.py`

方案 D 的核心思想：

```text
当前帧
  -> 优先匹配最近关键帧
  -> 成功：相对关键帧定位
  -> 失败：回退相邻帧积分
  -> 定期更新关键帧
```

主要函数：`run_scheme_d()`

实现步骤：

1. 初始帧作为关键帧
2. 当前帧优先与关键帧匹配
3. 若匹配置信度足够：
   - 使用当前帧相对关键帧的位移
   - 预测位置 = 关键帧位置 + 相对位移
4. 若匹配失败：
   - 回退到上一帧匹配
   - 累积相邻帧位移
5. 到达 `keyframe_interval` 或匹配质量差时更新关键帧

适用场景：

- 短时间局部重叠较好
- 希望降低相邻帧积分漂移

局限：

- 若关键帧匹配方向本身错误，仍会漂移
- 大尺度转弯和弱纹理下仍依赖稳定匹配
- 当前实现是关键帧匹配，不是真正全局回环或 bundle adjustment

## 6. 匹配后端 `RobustMatcher`

文件：`run_matching_experiments.py`

`RobustMatcher` 是方案 B/D 的统一匹配接口。

### 6.1 ORB / SIFT 后端

函数：`motion()`

实现：

1. `detectAndCompute()` 提取特征和描述子
2. BFMatcher KNN 匹配
3. Lowe ratio test 过滤
4. RANSAC 估计 `estimateAffinePartial2D`
5. 用图像中心经过仿射后的位移作为 `dx/dy`

输出：`MatchMotion`

字段：

- `dx`, `dy`
- `rotation_deg`
- `scale`
- `confidence`
- `num_matches`
- `num_inliers`
- `backend`

### 6.2 LoFTR 后端

函数：`_init_loftr()`、`_motion_loftr()`

实现：

1. 加载 `Kornia LoFTR(pretrained="outdoor")`
2. 将图像缩放到 `--loftr-width` x `--loftr-height`
3. 转为 `[1, 1, H, W]` 的 torch tensor
4. LoFTR 输出 `keypoints0`、`keypoints1`、`confidence`
5. 按置信度过滤低质量匹配
6. 将点坐标缩放回原图尺寸
7. RANSAC 估计仿射
8. 输出 `MatchMotion`

注意：

```

若没有该文件，Kornia 会尝试从以下 URL 下载：

```

## 7. 关键工具函数

### 7.1 `rotate_pixel_to_en()`

文件：`run_matching_experiments.py`

功能：用固定 yaw 将像素位移转成地理 East/North 位移。

公式：

```text
east  = cos(yaw) * dx * mpp - sin(yaw) * dy * mpp
north = sin(yaw) * dx * mpp + cos(yaw) * dy * mpp
```

### 7.2 `pixel_to_geo_delta()`

文件：`utils/geo_utils.py`

功能：主流程中将像素位移转成经纬度增量。

返回：

- `delta_lon`
- `delta_lat`
- `east`
- `north`
- `mpp`

### 7.3 `estimate_yaw_deg()`

文件：`run_matching_experiments.py`

功能：方案 B/D 中用前若干帧视觉方向和 GPS 方向估计 yaw。

实现：

1. 对前 N 帧匹配得到视觉位移方向
2. 从 GPS 差分得到真实方向
3. 只使用单位方向向量
4. 用 2D Procrustes 求最优旋转角

该函数只使用 GPS 方向，不使用 GPS 距离。

## 10. 方案对比与后续建议

### 10.1 主流程

优点：

- 模块完整
- 有起始帧检测、内参估计、尺度估计、物理约束、EKF
- 输出诊断字段丰富

缺点：

- 对 yaw 观测仍不稳定
- 长航线累计误差大
- 纯单目下大幅拐弯仍难以可靠恢复

### 10.2 方案 B

优点：

- 结构简单
- 便于替换深度匹配器
- 适合验证匹配前端质量

缺点：

- 相邻帧积分漂移明显
- 不使用局部地图约束

### 10.3 方案 D

优点：

- 比方案 B 多了关键帧局部约束
- 能减少一部分短期积分漂移
- 适合扩展为局部 mosaic / 滑窗优化

缺点：

- 当前只是关键帧匹配，还不是完整 SLAM
- 关键帧匹配失败时仍会回退到相邻帧漂移

### 10.4 推荐下一步

1. 先下载 LoFTR 权重，跑 `--matcher loftr` 的 1000 帧对比。
2. 若 LoFTR 的匹配方向明显改善，再把 LoFTR 接入主流程 `FeatureTracker`。
3. 若 LoFTR 仍无法解决转弯，说明仅靠下视红外图像恢复航向非常困难，应接入 IMU yaw / 云台 yaw。
4. 若坚持纯视觉，应将方案 D 扩展为局部 mosaic + 滑窗优化，而不是只做关键帧匹配。
